# Book Club Bot

Telegram-бот для книжного клуба, который автоматически отправляет ежедневные отчёты о прогрессе чтения из Google Sheets.

## Что делает бот

- **Рейтинг участников** — кто сколько дней читал за спринт (с медалями)
- **Лидер спринта** — выделяет лучшего читателя
- **Стрики** — считает дни подряд (даже через несколько спринтов)
- **Прогресс общей книги** — сколько человек дочитали
- **Список книг** — кто что сейчас читает
- **Обратный отсчёт** — показывает сколько дней до конца спринта
- **Предупреждение** — выделяет последний день спринта
- **Кнопка «Открыть таблицу»** — нативная Telegram-кнопка под сообщением
- **Сравнение со спринтом** — на сколько % клуб стал читать больше/меньше, чем в прошлый раз
- **Живые вставки** — приветствие по дню недели и случайная цитата о чтении в каждом отчёте
- **Бейджи** — 🎯 идеальный спринт, 💎/🌟 бейджи за долгий стрик (хранятся на скрытом листе `Achievements`)
- **Игровые механики** — церемония итогов спринта, бейджи за прогресс (🚀 рывок, 🔄 камбэк, 🏁 первым дочитал), 🔮 секретные бейджи, 🧊 заморозка стрика, ⚔️ дуэли, 🎭 тайные напарники с анонимными посланиями, цитаты участников в отчёте, вопросы к встрече, голосование за следующую книгу — см. раздел [«Игровые механики»](#игровые-механики)
- **Команды в Telegram** — `/meeting_done` (или текст «встреча закончена») присылает два опроса с временем следующей офлайн-встречи (суббота и воскресенье через 6 недель, по 12 слотов с 07:00 UTC+0, мультивыбор); `/another_time` сдвигает на неделю; `/bot_version` показывает версию бота

## Структура Google Sheets

Бот ожидает такую структуру таблицы:

### Левая часть (трекер чтения)
| A | B | C | D | ... |
|---|---|---|---|-----|
| | Георгий | Василий | Антон | ... |
| 06.01.2026 | ☑ | ☐ | ☑ | ... |
| 07.01.2026 | ☑ | ☑ | ☐ | ... |
| ... | ... | ... | ... | ... |

### Правая часть (информация о книгах)
| J | K | L |
|---|---|---|
| Основная книга спринта: | | |
| Общая книга | 1984 | |
| Дата обсуждения | 25 января | |
| Георгий | "Тёмный лес" | ☑ |
| Василий | "Мор" | ☐ |

### Листы
- Каждый спринт на отдельном листе: `Fortnight 98`, `Fortnight 97`, и т.д.
- Бот автоматически находит лист с максимальным номером

## Установка

### 1. Создать Telegram бота

1. Открыть [@BotFather](https://t.me/BotFather) в Telegram
2. Отправить `/newbot`
3. Придумать имя боту
4. Скопировать токен (выглядит как `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`)

### 2. Получить Chat ID группы

1. Добавить бота в группу книжного клуба
2. Сделать бота администратором (чтобы мог писать)
3. Отправить любое сообщение в группу
4. Открыть в браузере:
   ```
   https://api.telegram.org/bot<ТОКЕН>/getUpdates
   ```
5. Найти в ответе `"chat":{"id": -XXXXXXXXX}` — это Chat ID

### 3. Добавить скрипт в Google Sheets

В проекте Apps Script два файла: **`Config.gs`** (ваши личные значения,
создаётся один раз и больше не трогается) и **`Bot.gs`** (вся логика,
обновляется при каждом апдейте бота). Так обновление кода никогда не
затирает токены.

1. Открыть таблицу книжного клуба → **Расширения** → **Apps Script**
2. Создать файл **Config.gs**: слева «Файлы» → **+** → **Скрипт** → назвать `Config`.
   Вставить туда содержимое `Config.example.gs` и заменить плейсхолдеры на свои
   значения (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET`;
   `WEB_APP_URL` заполняется позже, после деплоя — см. раздел про команды).
3. В файл `Bot.gs` (или как называется основной файл — `Код.gs`) вставить
   код из `BookClubBot.gs` **целиком вместо старого**. Копировать через
   кнопку **Raw** на GitHub — при копировании с обычной страницы могут
   потеряться символы.
4. Сохранить (Ctrl+S / Cmd+S)

**При последующих обновлениях** повторяется только шаг 3 — `Config.gs`
не трогается. Если в старом `Bot.gs` ещё оставались константы с токеном
наверху — их надо убрать (они теперь только в `Config.gs`), иначе будет
ошибка «Identifier has already been declared».

### 4. Настроить автоматическую отправку

1. В редакторе Apps Script выбрать функцию `setupDailyTrigger`
2. Нажать **Выполнить**
3. Разрешить доступ (Google попросит подтверждение)
4. Готово! Отчёт будет приходить **каждый день в 19:00 MSK**

Проверить логику бота локально (без Google): `node First-Project/test/run_tests.js`

## Особенности

### Динамическое определение данных
- **Участники** — добавляй сколько угодно, бот найдёт всех до первой пустой ячейки
- **Дни спринта** — хоть 14, хоть 21 день, считается по датам в колонке A
- **Секция книг** — находится по заголовку "Основная книга"
- **Объединённые ячейки** — бот корректно обрабатывает merged cells

### Умные стрики
Стрик считается по **имени** участника, а не по номеру колонки. Это значит:
- Можно менять порядок участников между спринтами
- Стрик продолжается через границы спринтов
- Будущие дни спринта не считаются, сегодняшний неотмеченный день — тоже
  (ещё успеешь отметиться), а вот **прошедший неотмеченный день — пропуск**
- Пропуск обнуляет стрик, если нет 🧊 заморозки (см. «Игровые механики»)
- Новый участник получит стрик с 0

### Эмодзи стриков
- ⚡ — 3-6 дней подряд
- 🔥 — 7-13 дней подряд
- 💎 — 14-29 дней подряд
- 🌟 — 30+ дней подряд

Стрик отображается только при 3+ днях подряд.

### Обратный отсчёт
В заголовке показывается сколько дней осталось до конца спринта:
- `(осталось 5 дней до конца спринта)`
- `(осталось 3 дня до конца спринта)`
- `(остался 1 день до конца спринта)`
- `(последний день спринта!)`

### Автосоздание нового спринта
В последний день спринта бот сам копирует лист, увеличивает номер на 1,
заполняет новые даты (**настоящими** датами, не текстом — это важно для
корректной работы отсчёта на следующем спринте) и сбрасывает чекбоксы.
Защищено от двойного срабатывания (`LockService` + проверка на уже
существующий лист с таким именем). Если создание всё же не удалось —
в Telegram придёт отдельное предупреждение, и спринт можно будет создать
вручную через меню.

### Бейджи
Хранятся на отдельном скрытом листе `Achievements` (создаётся автоматически
при первой выдаче). Сейчас доступны только бейджи, которые можно посчитать
из уже имеющихся данных, без хранения истории по дням:
- 🎯 «Идеальный спринт» — 100% отмеченных дней, выдаётся один раз за спринт
- 💎 «Стрик 14+» / 🌟 «Стрик 30+» — выдаются один раз за всё время

### Команды в Telegram — дата следующей встречи клуба
Встреча клуба — отдельная штука от «Дата обсуждения» общей книги, обычно
раз в 6 недель. Раньше дату выставляли руками в таблице, теперь это делает
Telegram-опрос по команде:

- **`/meeting_done`** (или просто текст «встреча закончена») — «встреча
  прошла». Бот считает дату `сегодня + 6 недель`, находит ближайшие субботу
  и воскресенье и присылает в чат **два опроса**: один на субботу, один на
  воскресенье. В каждом — 12 временных слотов из `MEETING_TIME_SLOTS` (с 07:00, время UTC+0 указано в вопросе),
  **можно выбирать несколько**. Участники голосуют прямо в опросах, бот
  ничего никуда не записывает — итог виден в самих опросах.
- **`/another_time`** — если предложенные выходные не подошли, эта команда
  сдвигает предложение ещё на неделю вперёд и присылает новую пару опросов.
- **`/bot_version`** — бот отвечает версией кода, который сейчас реально
  задеплоен. Первое, что стоит написать после любого обновления.

Защита от лишних опросов — двухуровневая: повторная доставка одного и того
же сообщения от Telegram (`update_id`) игнорируется всегда; новая команда
раньше чем через 2 минуты после предыдущей — тоже. Так что даже если
несколько человек нажмут команду одновременно или Telegram начнёт
переотправлять апдейты, в чат уйдёт ровно одна пара опросов.

Текстовый триггер «встреча закончена» (без слэша) работает, только если у
бота выключен Privacy Mode (@BotFather → `/mybots` → бот → Bot Settings →
Group Privacy → Turn off). Команда `/meeting_done` работает всегда.

**Это единственная механика бота, которая требует разовой ручной настройки
за пределами кода** — команды приходят в бот *извне* (в отличие от всего
остального, что бот сам рассылает по расписанию), а чтобы Apps Script мог
получать входящие сообщения, его нужно один раз опубликовать как веб-адрес
и сообщить этот адрес Telegram.

#### Разовая настройка вебхука

1. Убедиться, что в `Config.gs` заполнен `TELEGRAM_WEBHOOK_SECRET` (любая
   длинная случайная строка).
2. В редакторе Apps Script: **Deploy → New deployment**
   → тип **Web app** → Execute as: **Me** → Who has access: **Anyone**
   → **Deploy**. Скопировать выданный адрес вида
   `https://script.google.com/macros/s/XXXXXXXX/exec`.
3. Вписать этот адрес в `WEB_APP_URL` в `Config.gs`, сохранить.
4. В редакторе выбрать функцию `setupTelegramWebhook` и нажать **Выполнить**
   (аргументы не нужны — адрес берётся из `WEB_APP_URL`). В логе должно
   появиться `"ok":true` дважды — для `setWebhook` и для `setMyCommands`.
5. Проверить: `/bot_version` в чате клуба → бот отвечает версией.
   Затем `/meeting_done` → приходят два опроса.

**Важно и легко забыть:** если после этого правишь код — простого сохранения
недостаточно. Нужно **Deploy → Manage deployments → значок карандаша у
Web app → Version: New version → Deploy**. Адрес при этом не меняется,
вебхук перенастраивать не нужно. Если же создать **New deployment** —
адрес будет новый, и надо повторить шаги 3–4.

**Почему `doPost` ничего не возвращает.** Если вернуть из `doPost`
`ContentService.createTextOutput(...)`, Apps Script отдаёт этот текст через
`302`-редирект на `script.googleusercontent.com`. Telegram по редиректам не
ходит, считает доставку проваленной («Wrong response from the webhook: 302
Found») и переотправляет апдейт снова и снова — так и рождались лавины
одинаковых опросов. Пустой ответ Apps Script отдаёт напрямую с `200`, что
Telegram и нужно. Не добавляйте `return` в `doPost`.

#### Обновление кода через clasp (без копипаста)
Проще всего обновлять бота утилитой Google `clasp`: она заливает файлы и
выпускает новую версию деплоя из терминала, ничего не нужно вставлять руками.
Разово: включить Apps Script API на https://script.google.com/home/usersettings,
`npm install @google/clasp`, `clasp login`, `clasp clone <Script ID>`
(Script ID — в настройках проекта). `Config.gs` живёт только в локальной
папке clasp и в проекте Apps Script, в git не попадает. Дальше каждое
обновление: скопировать `BookClubBot.gs` в `Бот.js`, `clasp push -f`,
`clasp deploy -i <ID деплоя> -d "описание"` — ID деплоя показывает
`clasp deployments`.

## Игровые механики

Задача — чтобы бот был не «очередным сообщением в чате», а поводом
писать друг другу. Всё работает поверх той же таблицы: галочка = день,
когда человек читал минимум полчаса.

### Как начать (один раз)
1. Обновить код и выпустить **New version** деплоя (см. «Разовая настройка
   вебхука»), затем **ещё раз запустить `setupTelegramWebhook`** — так в меню
   Telegram появятся новые команды.
2. Каждый участник пишет в чате клуба **`/iam Имя`** — имя как в таблице.
   Это привязка Telegram-аккаунта к колонке в таблице; без неё не работают
   дуэли, тайные напарники и анонимки.
3. Каждый участник открывает бота в личке и нажимает **Start** — иначе
   Telegram не даст боту написать ему первым (бот не сможет сообщить, кому
   ты тайный напарник; тогда поможет `/my_target` в личке).
4. Бот должен оставаться **администратором** группы — так он сможет удалить
   `/anon`, если кто-то по ошибке напишет его в общий чат.

Privacy Mode выключать не нужно: все новые механики работают через
/команды, кнопки и личку.

### 🏆 Церемония итогов спринта
В последний день спринта, сразу после отчёта, приходит отдельный пост:
👑 MVP, 🚀 рывок спринта, 🔥 самый длинный стрик, 🔄 камбэки,
🏁 кто первым дочитал общую книгу, ⚔️ итоги дуэлей, 🎭 раскрытие тайных
напарников (кто кого опекал и сколько посланий отправил), число выданных
🔮 секретных бейджей. Следом — голосование за следующую общую книгу.

### 🎖 Бейджи за прогресс
- 🚀 **Рывок спринта** — самый большой рост своего % к прошлому спринту
  (выдаётся на церемонии).
- 🔄 **Камбэк** — перерыв 3+ дня, потом 3+ дня чтения подряд (раз за спринт).
- 🏁 **Первым дочитал общую книгу** — раз на книгу; если дочитали в один
  день несколько человек — получают все.
- 🧊 **Заморозка стрика** — каждые 7 дней стрика дают заморозку (копится
  до 2). Пропущенный день съедает заморозку вместо стрика. Остаток видно в
  рейтинге: `🔥12 🧊1`.

Хранятся на скрытом листе `Achievements`, как и старые бейджи.

### 🔮 Секретные бейджи
В чате объявляется только название — за что, участники гадают сами.
Каждый выдаётся один раз за всё время. Условия (не рассказывайте клубу 🤫):

| Бейдж | Условие |
|-------|---------|
| 🎢 Американские горки | 6 дней подряд строго через день: читал / не читал / … |
| 🌅 Сильный финиш | первые 3 дня спринта пропущены, последние 3 — отмечены |
| 🏖 Выходной читатель | все наступившие выходные спринта (минимум 4 дня) отмечены |
| ⚖️ Золотая середина | ровно половина дней спринта |
| 🧊 Ледяное сердце | стрик спасла заморозка |
| 💬 Цитатник | 3+ цитаты через `/quote` |
| 🤔 Почемучка | 3+ вопроса через `/question` |
| 📮 Почтальон | 3+ анонимных послания за спринт |
| 🗡 Гладиатор | 3 выигранные дуэли |

Условия вроде «читал после полуночи» или «в день рождения» из таблицы не
посчитать (там нет времени отметки и дней рождения), поэтому их нет.

### 💬 Цитаты участников — `/quote текст`
Цитата из своей книги. В ближайшем отчёте она появится вместо случайной
цитаты, с подписью, кто прислал. Каждая показывается один раз. Можно
писать в чат или тихо — в личку боту.

### ❓ Вопросы к встрече — `/question текст`, `/questions`
Вопросы по общей книге копятся весь спринт (можно в личке — тогда никто
не узнает автора). `/questions` показывает текущий список. **За день до
«Дата обсуждения»** из таблицы бот сам публикует список. Дата понимается
как настоящая дата, `25.01.2026` или `25 января`.

### 📚 Следующая книга — `/suggest_book название`, `/book_vote`
Предложения копятся (дубли отсекаются). В последний день спринта, если
кандидатов 2+, бот запускает опрос «Какую книгу читаем следующей общей?»
(один голос, до 10 вариантов). Запустить голосование в любой момент —
`/book_vote` (например, сразу после встречи).

### ⚔️ Дуэли — `/duel Имя` или `/duel @username`
Под вызовом кнопка «⚔️ Принять вызов» — нажать может только вызванный,
вызов действует сутки. Дуэль идёт 7 дней с момента принятия: кто больше
дней отметит в таблице. На следующий день после окончания бот объявляет
счёт, победителя и случайный фант для проигравшего. У одного человека —
одна активная дуэль.

### 🎭 Тайные напарники и анонимки
В первый ежедневный отчёт нового спринта бот случайно назначает каждому,
кто сделал `/iam`, подопечного (по кругу — у каждого ровно один тайный
напарник; нужно минимум 3 человека). Каждому приходит в личку, кого он
опекает. Дальше всё — **в личке с ботом**:
- `/anon текст` — послание подопечному; в чат уходит
  «📨 Маша, тебе послание от тайного напарника: …» без имени отправителя
  (пока подопечного нет — бот подскажет `/anon_all`, а не отправит молча);
- `/anon_all текст` — анонимное послание всему клубу;
- `/my_target` — напомнить, кто твой подопечный.

Лимит — 5 анонимок за несколько часов на человека. Пока только текст.

**Насколько это анонимно.** В чате имя отправителя не появляется нигде:
ни в посланиях, ни в бейджах (📮 Почтальон выдаётся только в последний
день, вместе с раскрытием пар, и только за послания подопечному), ни на
церемонии. Послания всему клубу (`/anon_all`) бот вообще не связывает с
человеком — лимит считается во временном кэше. Но: таблица — общая, а
скрипт привязан к ней, поэтому любой **редактор** таблицы технически может
открыть Apps Script → Project Settings → Script Properties и увидеть
назначенные пары тайных напарников (`secretPartners`). Это надо специально
лезть — но если для клуба это важно, договоритесь туда не заглядывать.

### Где хранятся данные
- Скрытые листы `Quotes`, `Questions`, `BookSuggestions`, `Achievements`
  (создаются сами при первой записи).
- Script Properties (Apps Script → Project Settings): `telegramMembers`
  (кто есть кто), `duels`, `duelWins`, `secretPartners`. Если что-то пошло не так, ключ можно удалить —
  механика начнёт заново.

## Troubleshooting

### Бот не отправляет сообщения
1. Проверь токен бота
2. Проверь Chat ID (должен начинаться с `-` для группы)
3. Убедись, что бот добавлен в группу и является админом

### Не находит данные
1. Проверь, что лист называется `Fortnight XX` или `Fortnite XX`
2. Проверь, что в правой части есть текст "Основная книга"

### Стрик неправильно считается
1. Убедись, что имена участников одинаковые на всех листах (с учётом регистра)
2. Проверь, что в колонке A текущего спринта — настоящие даты (или текст
   вида `06.01.2026`): по ним бот понимает, какие дни уже прошли
3. Запусти `debugStreaks()` чтобы увидеть как считаются стрики

### Тайному напарнику не пришло сообщение в личку
Telegram не даёт боту написать первым. Нужно открыть бота в личке, нажать
**Start** и отправить `/my_target`.

### Не все участники в "Сейчас читают"
Если в таблице объединённые ячейки — это нормально, бот их обрабатывает. Если проблема осталась, проверь что имена не содержат слов "книга", "дата", "спринт".

### `/meeting_done` или `/another_time` не отвечают
1. Проверь, что деплой Web App активен и Who has access стоит **Anyone**
   (не «Only myself» — иначе Telegram не сможет достучаться).
2. Проверь, что после последнего изменения кода делал **New version** в
   Manage deployments (см. раздел про вебхук выше) — иначе выполняется
   старая версия `doPost`.
3. Открой **Executions** в Apps Script (боковое меню) — там видно, долетел
   ли запрос от Telegram и что произошло: неверный `secret` в URL, не тот
   `chat_id`, ошибка парсинга.
4. Проверь `TELEGRAM_WEBHOOK_SECRET` в `Config.gs` совпадает с тем, что был
   при последнем запуске `setupTelegramWebhook` — если менял секрет, нужно
   заново запустить настройку.
5. Открой в браузере `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`.
   Если там `"last_error_message":"Wrong response from the webhook: 302 Found"`
   — значит задеплоена старая версия, где `doPost` возвращал
   `ContentService` (см. «Почему doPost ничего не возвращает»). Обнови код
   и выпусти New version. Если `pending_update_count` большой — сбрось
   очередь: `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook?drop_pending_updates=true`,
   потом заново `setupTelegramWebhook`.
6. Быстрая проверка снаружи: `curl -s -o /dev/null -w "%{http_code}" -X POST
   -H "Content-Type: application/json" -d '{"update_id":1}' "<WEB_APP_URL>?secret=<секрет>"`
   должно вернуть `200`. Если `302` — проблема из пункта 5.

### В чат прилетает много одинаковых опросов
С версии `2026.09.04-2` такого быть не должно: Telegram получает `200` и
не переотправляет апдейты, повторы по `update_id` отсекаются, плюс
2-минутный cooldown. Если всё же случилось — напиши `/bot_version`: если
бот молчит или отвечает старой версией, значит обновление не доехало
(см. «New version» выше).
